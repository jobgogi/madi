madi 서비스 청사진

일본어·한국어 번역 학습 앱 madi의 데이터 구조와 화면 사용법을 사용자 기능과 관리자 기능 양쪽 다 한 장에 정리한다. ERD, 두 개의 플로우 다이어그램, 화면별 사용 가이드, 남은 미결 사항 순.

프롬프트 해석 플로우

시스템 프롬프트는 더 이상 코드에 하드코딩되지 않는다. DB의 활성 템플릿(편집 가능)과 코드에 고정된 LOCKED_PROMPT_RULES(카테고리 enum·배치 처리·출력 형식)가 요청마다 합쳐진다.

app/api/analyze/route.ts → lib/providers/analyze.ts

사용자 학습 플로우

사용자 화면 가이드

일반 사용자(학습자)가 실제로 거치는 화면들.

/onboarding/language

온보딩

최초 로그인 시 모국어(한국어/일본어)를 선택한다 — 이후 모든 리포트의 설명 텍스트 언어와 JLPT/TOPIK 표기 기준이 된다.

  1. 브라우저 언어를 감지해 기본값으로 제시
  2. 선택 후 대시보드로 이동
/dashboard

대시보드

학습 현황을 한눈에 본다 — 잔디 그래프, 자주 틀리는 카테고리, 방향 필터, 최근 기록.

  1. 잔디 그래프에서 날짜별 학습량 확인(5단계 명도)
  2. 카테고리 카드 클릭 → 해당 카테고리로 필터링된 기록으로 이동
  3. 방향(전체 / 日→韓 / 韓→日) 탭으로 필터링
/new → /new/translate

새 학습

원문을 입력하고 문장 단위로 직접 번역한 뒤, 한 번에 분석을 요청한다.

  1. 방향 선택 후 원문 입력(자동 문장 분리)
  2. 문장마다 번역 작성 — 진행률 표시
  3. 전체 작성 완료 후 "분석 시작"(문장 수와 무관하게 API 1회 호출)
전제 설정 화면에 API 키가 없으면 진입 전 안내 배너가 뜬다.
/history/[id]

리포트

AI 기준역과 내 번역을 대조하고, 잘한 점·아쉬운 점·이전 대비 성장을 확인한다.

  1. 문장별 비교(색상 대조), 문법·어휘 지적 사항 확인
  2. 난이도 배지(JLPT/TOPIK) 및 총평 확인
  3. 👍/👎로 이 리포트(= 사용된 프롬프트 버전)를 평가
/settings

설정

LLM provider와 API 키를 등록한다(BYOK — 서버에 저장되지 않고 브라우저 localStorage에만 남는다).

  1. provider 선택(Claude / ChatGPT / Gemini)
  2. API 키 입력 후 "연결 테스트"로 유효성 확인

관리자 화면 가이드

/admin은 URL 직접 입력으로만 접근한다(의도적으로 진입 링크를 두지 않음). profiles.role = 'admin'이 아니면 /dashboard로 리다이렉트된다.

/admin/prompt-templates

프롬프트 템플릿

방향별(일→한 / 한→일) 시스템 프롬프트 버전을 관리하고, 저장 전에 실제 LLM으로 미리 테스트한다.

  1. 방향 선택 후 본문 작성 — 고정 규칙은 하단 토글에서 확인만(입력 불필요)
  2. 저장하면 비활성 상태로 새 버전 생성
  3. 원문·번역 샘플로 "테스트 실행" → 결과 확인 후 "활성화"
  4. 활성화 시 같은 방향의 기존 버전은 자동 비활성
주의 테스트 실행은 결과를 저장하지 않는다 — 버전별 👍/👎 집계에 반영하려면 실제 /new 분석 후 리포트 화면에서 피드백을 남겨야 한다.
/admin/error-categories

에러 카테고리

고정 10종 카테고리의 표시 label을 인라인으로 수정한다.

  1. 목록에서 label 클릭 후 수정
  2. 저장 즉시 반영, 새로고침해도 유지
갭 여기서 바꾼 label은 실제 서비스 화면(CATEGORY_LABEL 상수)에는 아직 연결되지 않는다.
/admin/users

사용자·권한

가입일, 최근 로그인, 모국어를 보고 권한(user ↔ admin)을 전환한다.

  1. 대상 사용자의 권한 변경 버튼 클릭
  2. 확인 창에서 재확인 후 반영
보호 로그인한 본인 행은 변경 버튼이 비활성화된다 — 자기 강등 방지. 이메일은 표시되지 않는다(사용자 ID 기준).
/admin/stats

통계 대시보드

전체 가입자·리포트 수, 방향별/provider별 집계, 최근 10일 가입 추이를 본다.

  1. 상단 카드에서 누적 지표 확인
  2. 하단 막대그래프에서 최근 10일 추이 확인(막대에 마우스오버 시 날짜·건수)
참고 개인 대시보드의 잔디 그래프와는 별개 — 전체 사용자 합산 지표만 다룬다.

미결 사항

기능 결함이 아니라 의도적으로 범위 밖에 둔 것들.

항목현재 상태비고
관리자 최초 지정 update profiles set role='admin' ... 수동 SQL만 존재
에러 카테고리 label 연동 admin 화면 ↔ CATEGORY_LABEL 상수 분리 서비스 화면 반영 안 됨
관리자 진입 링크 URL 직접 입력만 의도적 결정
